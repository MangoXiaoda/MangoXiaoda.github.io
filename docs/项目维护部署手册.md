# 夏天去旅行博客项目维护部署手册

最后更新：2026-05-13

## 1. 项目简介

这是一个个人博客静态站点项目，当前线上地址是：

```text
https://mangoxiaoda.github.io/
```

项目使用：

- Hugo：静态站点生成器，负责把 Markdown 内容构建成 HTML 页面。
- Hugo Dream 主题：博客前台主题，本项目已经对主题模板做了定制。
- Sveltia CMS / Decap CMS 配置：提供 `/admin/` 后台编辑入口。
- GitHub Pages：当前线上托管方式。
- GitHub Actions：每次推送到 `main` 分支后自动构建并部署。

这个项目没有传统后端数据库。文章、图片、配置和模板都存在 Git 仓库里。它的核心优势是轻量、稳定、成本低，维护重点是保护好 Git 仓库和图片内容。

## 2. 当前仓库信息

```text
GitHub 仓库：https://github.com/MangoXiaoda/MangoXiaoda.github.io.git
默认分支：main
线上根地址：https://mangoxiaoda.github.io/
本地目录：/Applications/ServBay/www/wind-dream-cms-blog
```

GitHub Pages 用户站点仓库通常使用 `用户名.github.io` 命名，因此当前仓库可以直接映射到 `https://mangoxiaoda.github.io/`。

## 3. 目录结构说明

```text
.
├── hugo.toml                         # Hugo 主配置，站点名称、域名、主题参数
├── package.json                      # 本地开发和构建脚本
├── .github/workflows/deploy.yml      # GitHub Pages 自动部署流程
├── static/admin/                     # 后台 CMS 页面和配置
├── static/img/                       # 静态图片，例如头像、默认封面、上传图片
├── content/about/                    # 关于页内容
├── content/posts/                    # 文章内容，每篇文章通常是一个独立文件夹
├── themes/hugo-theme-dream/          # Dream 主题及本项目定制过的模板
├── public/                           # Hugo 构建产物，本地生成，不建议手动编辑
└── docs/                             # 项目维护文档
```

重点文件：

- `hugo.toml`：改站点标题、头像、副标题、主题参数、线上域名。
- `static/admin/config.yml`：改后台文章字段、仓库地址、上传目录。
- `content/posts/**/index.md`：文章正文和文章元信息。
- `content/posts/**/图片文件`：文章自己的封面和正文图片。
- `themes/hugo-theme-dream/layouts/_default/summary.html`：首页卡片样式。
- `themes/hugo-theme-dream/layouts/_default/single.html`：文章详情页样式。
- `themes/hugo-theme-dream/layouts/partials/nav.html`：顶部导航。
- `themes/hugo-theme-dream/layouts/partials/footerLeft.html`：底部版权。
- `.github/workflows/deploy.yml`：GitHub 自动部署流程。

## 4. 本地开发

首次拉取或换电脑后，进入项目目录：

```bash
cd /Applications/ServBay/www/wind-dream-cms-blog
npm install
```

启动前台预览：

```bash
npm run dev
```

默认访问：

```text
http://127.0.0.1:1313/
```

同时启动前台和本地 CMS：

```bash
npm run dev:all
```

本地后台访问：

```text
http://127.0.0.1:1313/admin/
```

构建检查：

```bash
npm run build
```

如果遇到本机缓存目录权限问题，可以使用：

```bash
npm run build -- --cacheDir ./resources/_gen/cache
```

## 5. 日常写作和内容维护

### 5.1 使用后台写文章

打开：

```text
https://mangoxiaoda.github.io/admin/
```

或本地：

```text
http://127.0.0.1:1313/admin/
```

后台字段说明：

- 标题：文章标题。
- 发布时间：文章发布日期。
- 更新时间：可选。
- 作者：默认是 `夏天去旅行`。
- 封面：文章列表和详情页显示的封面图。
- 分类：适合放大类，例如 `随记`、`旅行`、`技术`。
- 标签：适合放更细的关键词，例如 `演唱会`、`照片`、`生活`。
- 正文：Markdown 内容。

当前首页文章卡片会显示：

- 封面图
- 标题
- 日期
- 右下角标签

不会显示摘要、作者和阅读时间。

### 5.2 直接编辑 Markdown

文章通常位于：

```text
content/posts/文章目录/index.md
```

示例结构：

```markdown
---
draft: false
title: 记录第一次看演唱会
date: 2026-04-25T19:33:00+08:00
lastmod: ''
author: 夏天去旅行
cover: 微信图片_20260426140943_57_172.jpg
categories:
  - 随记
tags:
  - 演唱会
---

这里写正文。
```

如果封面图片放在同一篇文章目录下，`cover` 可以直接写文件名：

```yaml
cover: 微信图片_20260426140943_57_172.jpg
```

如果图片放在 `static/img/` 下，路径通常写成：

```yaml
cover: /img/sample-cover.svg
```

建议优先使用“文章目录 + index.md + 同目录图片”的方式，这样一篇文章的内容和图片在一起，迁移和备份更清晰。

## 6. 常用维护流程

每次本地修改前先同步线上仓库：

```bash
git pull --rebase origin main
```

修改后本地构建检查：

```bash
npm run build
```

查看改动：

```bash
git status
git diff
```

提交：

```bash
git add .
git commit -m "描述这次修改"
git push origin main
```

推送成功后，GitHub Actions 会自动部署。通常几十秒到几分钟后线上生效。

## 7. 当前 GitHub Pages 部署方式

当前部署流程在：

```text
.github/workflows/deploy.yml
```

流程逻辑：

1. 推送到 `main` 分支。
2. GitHub Actions 拉取代码。
3. 安装 Hugo `0.161.1 extended`。
4. 执行：

```bash
hugo --minify
```

5. 把 `public/` 目录作为 GitHub Pages 产物发布。

你平时不需要手动上传 `public/`，只要提交源码即可。

GitHub 仓库设置里建议保持：

- Pages Source：GitHub Actions
- 默认分支：main
- Actions 权限允许 Pages 部署

## 8. 线上后台登录说明

当前后台配置在：

```text
static/admin/config.yml
```

核心配置：

```yaml
backend:
  name: github
  repo: MangoXiaoda/MangoXiaoda.github.io
  branch: main
```

这表示后台会把文章改动提交回 GitHub 仓库。

如果线上 `/admin/` 登录失败，常见原因是 GitHub OAuth 没有配置好。可选方案有三种：

1. 本地写作：使用 `npm run dev:all`，通过本地后台编辑，再用 Git 推送。
2. GitHub 网页编辑：直接在 GitHub 仓库里编辑 Markdown 文件。
3. 配置 OAuth 代理：给 CMS 配置可用的 OAuth proxy，然后在 `static/admin/config.yml` 里打开 `base_url`。

本地后台最稳定，适合自己维护；线上后台更方便，但需要额外处理 GitHub 登录授权。

## 9. 未来部署到服务器

以后如果你想部署到自己的服务器，推荐仍然保持“源码在 GitHub，服务器只部署构建产物”的方式。

### 9.1 服务器静态部署方案

适合场景：只展示博客，不需要传统后端。

服务器需要：

- Linux 服务器
- Nginx
- Git
- Hugo extended，版本建议与当前一致：`0.161.1`
- Node.js 可选，本项目本身构建主要依赖 Hugo

服务器目录建议：

```text
/var/www/blog-source     # 源码仓库
/var/www/blog-public     # 构建后的 public 目录
```

部署步骤示例：

```bash
cd /var/www
git clone https://github.com/MangoXiaoda/MangoXiaoda.github.io.git blog-source
cd blog-source
hugo --minify --destination /var/www/blog-public
```

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    root /var/www/blog-public;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

启用 HTTPS 后再加 Certbot 或其他证书方案。

### 9.2 自动部署到服务器

以后可以选一种：

方案 A：服务器定时拉取

```bash
cd /var/www/blog-source
git pull --rebase origin main
hugo --minify --destination /var/www/blog-public
```

可以用 crontab 定时执行，但不是最优雅。

方案 B：GitHub Actions 通过 SSH 部署

1. 服务器创建部署用户。
2. GitHub 仓库配置 SSH 私钥到 Secrets。
3. Actions 构建 `public/`。
4. 用 `rsync` 上传到服务器目录。

大致命令：

```bash
rsync -avz --delete public/ deploy@example.com:/var/www/blog-public/
```

方案 C：服务器自己构建

GitHub Actions 只通知服务器执行部署脚本。服务器脚本负责 `git pull` 和 `hugo` 构建。

推荐优先级：

1. 小博客：GitHub Pages 继续用，最省心。
2. 有自定义域名、访问控制、更多服务时：Nginx 静态部署。
3. 有评论系统、搜索服务、图床、统计等动态能力时：服务器部署更灵活。

### 9.3 切换服务器时要改什么

如果换域名，例如：

```text
https://example.com/
```

需要改：

```toml
baseURL = "https://example.com/"
```

如果继续使用 GitHub 作为源码仓库，`static/admin/config.yml` 的 `repo` 不需要改。

如果换到其他 Git 仓库，则要改：

```yaml
backend:
  repo: 新用户名/新仓库名
```

如果服务器不是部署在根路径，而是部署在子路径，例如：

```text
https://example.com/blog/
```

则 `baseURL` 要写成：

```toml
baseURL = "https://example.com/blog/"
```

但更推荐博客部署在域名根路径，路径问题更少。

## 10. 备份策略

这个项目最重要的资产是：

- Git 仓库源码
- `content/` 下的文章
- `content/posts/` 下的文章图片
- `static/img/` 下的头像、默认图片、上传图片
- `hugo.toml`
- `static/admin/config.yml`
- `themes/hugo-theme-dream/layouts/` 下的定制模板
- `.github/workflows/deploy.yml`

不需要重点备份：

- `public/`：可以随时重新构建。
- `resources/_gen/`：缓存目录，可以重新生成。
- `node_modules/`：依赖目录，可以重新安装。

### 10.1 GitHub 作为主备份

当前 GitHub 仓库就是第一层备份。只要每次写完文章都提交并推送，内容就不会只存在本机。

推荐习惯：

```bash
git status
git add .
git commit -m "Add new post"
git push origin main
```

### 10.2 本地完整备份

可以定期把整个项目目录复制到移动硬盘或 iCloud/网盘：

```text
/Applications/ServBay/www/wind-dream-cms-blog
```

建议频率：

- 经常写文章：每周一次。
- 偶尔写文章：每月一次。
- 大改主题前：必须备份一次。

### 10.3 导出压缩包

在项目上一级目录执行：

```bash
tar -czf wind-dream-cms-blog-$(date +%Y%m%d).tar.gz wind-dream-cms-blog
```

恢复时解压即可。

### 10.4 多一份远端备份

除了 GitHub，也可以再建一个私有备份仓库，例如 Gitee、GitLab 或另一 GitHub 私有仓库：

```bash
git remote add backup git@github.com:你的用户名/blog-backup.git
git push backup main
```

以后可以同时推送：

```bash
git push origin main
git push backup main
```

### 10.5 如果以后使用评论系统

当前博客没有数据库。如果以后开启 Waline、Twikoo、Artalk 等评论系统，评论数据通常会存在数据库里，这部分不在 Hugo 仓库中。

届时需要额外备份：

- 评论数据库
- 评论服务配置
- 环境变量
- 对象存储里的附件

这是未来上服务器后最容易漏掉的备份点。

## 11. 恢复方案

### 11.1 换电脑恢复

```bash
git clone https://github.com/MangoXiaoda/MangoXiaoda.github.io.git
cd MangoXiaoda.github.io
npm install
npm run dev
```

如果目录名想保持现在这样：

```bash
git clone https://github.com/MangoXiaoda/MangoXiaoda.github.io.git wind-dream-cms-blog
```

### 11.2 GitHub Pages 出问题

检查顺序：

1. 打开 GitHub 仓库的 Actions 页面。
2. 查看最新一次 `Deploy Hugo site to GitHub Pages` 是否成功。
3. 如果构建失败，看日志里的 Hugo 报错。
4. 本地执行 `npm run build` 复现。
5. 修复后重新提交推送。

常见问题：

- Markdown front matter 格式错误。
- 图片路径写错。
- 文件名包含特殊字符但路径没有匹配。
- `baseURL` 配置错误。
- GitHub Pages 设置没有选择 GitHub Actions。

### 11.3 图片不显示

先判断图片放在哪里。

文章同目录图片：

```text
content/posts/某篇文章/index.md
content/posts/某篇文章/photo.jpg
```

对应：

```yaml
cover: photo.jpg
```

全局静态图片：

```text
static/img/photo.jpg
```

对应：

```yaml
cover: /img/photo.jpg
```

注意大小写和空格。线上 Linux 环境区分大小写，`Photo.jpg` 和 `photo.jpg` 是两个文件。

## 12. 版本升级建议

这个项目目前能稳定运行，不建议频繁升级主题和 Hugo。

建议升级节奏：

- Hugo：除非需要新功能或修安全问题，否则不急着升。
- Dream 主题：因为项目已经直接改了主题模板，升级前必须备份并对比改动。
- Sveltia CMS：当前通过 CDN 加载，若后台异常，再考虑锁定版本或调整 CDN。

升级前流程：

```bash
git pull --rebase origin main
git status
npm run build
git checkout -b upgrade-test
```

在测试分支验证没问题后再合并回 `main`。

## 13. 安全注意事项

- 不要把 GitHub Personal Access Token 写进仓库。
- 不要把服务器 SSH 私钥写进仓库。
- 不要把评论系统数据库密码写进仓库。
- 如果以后使用 GitHub Actions 部署服务器，密钥放在 GitHub Secrets。
- 后台 `/admin/` 是公开可访问页面，但真正写入仓库需要 GitHub 授权。

## 14. 推荐的长期维护习惯

每次写文章前：

```bash
git pull --rebase origin main
```

每次写文章后：

```bash
npm run build
git add .
git commit -m "Add post: 文章标题"
git push origin main
```

每次大改主题前：

```bash
git checkout -b theme-change
```

确认没问题再合并回 `main`。

每月做一次：

- 检查 GitHub Actions 最近部署是否正常。
- 本地跑一次 `npm run build`。
- 下载或复制一份完整项目备份。
- 检查新文章图片是否都在仓库里。
